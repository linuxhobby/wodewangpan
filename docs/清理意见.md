# 仓库配置文件去留意见书

日期：2026-11-20 · 背景：采集机已固定为 Debian，审查以下配置文件是否仍有必要。

## 结论速览

| 文件 | 结论 | 紧要度 |
|---|---|---|
| `.github/workflows/ci.yml` | 保留 | 删除即撤掉唯一自动质检 |
| `bot/` | 保留 | 运行中代码，与采集机无关 |
| `.gitattributes` | 保留 | 数据文件行尾契约 |
| `eslint.config.js` | 保留 | CI 与「提交前 lint」依赖 |
| `package.json` | 保留 | 构建核心依赖声明 |
| `package-lock.json` | 保留 | 与上者配对，锁版本 |
| `requirements.txt` | **删除** | 零依赖空壳 |
| `.vscode/settings.json` | 看习惯 | 仅编辑器体验，无功能影响 |

## 逐项论证

### 1. `.github/workflows/ci.yml` — 保留

GitHub Actions 在 push / PR 时自动执行 `npm ci → npm run lint → npm run build → npm run audit:css`。
它跑在 GitHub 的 ubuntu runner 上，与采集机是 Debian 还是别的系统毫无关系。删掉它等于把
「样式体检（漏样式 / 死样式 / 写死数值）」和「死代码拦截」两道自动防线全撤了——这两道防线
恰恰是 AGENTS.md 里「CSS 改动要克制，CI 有 audit:css 把关」承诺的兑现处。

### 2. `bot/` — 保留

TG 机器人于 2026-11-17 从私有仓并回本仓，是**在跑的代码**，不是遗留物。它的运行机不是
Debian 采集机（`菜单.vbs`、`TG机器人开机自启.vbs` 是 Windows 侧入口），两者互不替代。
另注意 `bot/scripts/notify-feishu.mjs` 被站内流程引用，动 bot/ 前先查依赖。

### 3. `.gitattributes` — 保留

当前唯一有效规则是 `data/*.yaml text eol=lf`。行尾统一与操作系统无关——Debian 上
core.autocrlf 的默认行为、未来任何一台新机器 clone，都靠它保证 `data/*.yaml` 不出现
CRLF 混排。AGENTS.md §5 明确引用了这份契约。历史段落里已移除的 bot VBS 规则随
2026-11-12 的迁移清理过，文件本身干净。

### 4. `eslint.config.js` — 保留

`npm run lint`（即 `eslint scripts tools theme/assets`）的规则载体，CI 第一步就是它，
AGENTS.md 也要求「提交前必须 0 错误」。删掉它 lint 直接报错，CI 全红。

### 5. `package.json` + `package-lock.json` — 保留

构建的核心依赖都在这里：`js-yaml`（解析全部 `data/*.yaml`）、`pinyin-pro`、`qrcode`
（构建期生成二维码），dev 侧 eslint + globals。VPS 发布和 Debian 构建都走
`npm ci`（lock 文件保证三机版本一致）。**删除任意一个，站点立即无法构建。**
这是全仓最不能动的两个文件之一。

### 6. `requirements.txt` — **建议删除**

文件打开只剩三行注释：「Python 侧（bot/app/）只用标准库，无第三方依赖；原 Pillow==12.3.0
仅供已移除的 QQ 扫码面板 scripts/qr_desktop.py 使用，不再需要」。它已经是一个零依赖空壳，
没有任何工具读它（bot 不用 pip，sitestats 用 python3 标准库），删除零风险。
若日后 Python 侧真引入第三方依赖，再新建即可。

### 7. `.vscode/settings.json` — 看使用习惯，删除无功能影响

内容仅三条：`git.ignoreLimitWarning`、关闭自动编码猜测、`*.vbs → vb` 语法关联 +
`[vb]` 强制 GBK 编码。不参与构建、CI、cron 的任何环节。

- 留下的理由：如果还用 VSCode 打开本仓，它能保证 `bot/菜单.vbs`、`菜单.hta`
  这批 GBK 编码的 Windows 入口文件不乱码——这正是它存在的唯一目的。
- 删除的理由：若不再用 VSCode 编辑本仓（尤其不在 Windows 侧看 bot/），它没有作用。

建议：**Windows 侧还在碰 bot/ 就留，只在 Debian 侧工作就删**。属个人偏好，不影响任何人。

## 已核实的事实依据

- `requirements.txt` 内容为纯注释，全仓无脚本读取它（grep 核实）。
- `bot/scripts/notify-feishu.mjs` 在站内流程中存在依赖关系，bot/ 不是孤岛。
- `ci.yml` 的四个步骤（lint/build/audit:css）均为 `package.json` scripts 里实际存在的命令。
- `.gitattributes` 有效性不依赖操作系统，Debian 亦是受益方。

## 执行建议

```bash
git rm requirements.txt          # 无争议，可直接执行
# .vscode/ 二选一：
git rm -r .vscode/               # 不再用 VSCode 编辑本仓时执行
```

本文档仅为意见记录，不构成自动执行的授权；实际删除仍按仓库惯例走人工确认 + commit。
