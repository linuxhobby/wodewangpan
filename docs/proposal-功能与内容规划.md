## 一、结论先行：四个瓶颈

现状完成度很高的部分：**静态化、SEO 基础设施、配图链路、标签近重复治理、蜘蛛流量治理**。这五块不用再加东西。真正的天花板在别处：

| # | 瓶颈 | 依据 |
|---|---|---|
| 1 | **内容同质化，缺差异化价值** | 每条 = 标题 + TMDB 简介 + 链接。简介已补到 300 字，但对搜索引擎仍是「同一份简介的第 N 个副本」。这是 [seo-收录与优化.md](seo-收录与优化.md) 里百度零抓取之外的第二个天花板 |
| 2 | **详情页是孤岛** | 资源页覆盖仅 159/702；详情页之间只靠 `relatedOf()`（`scripts/lib/render.js:537`）按标签交集给的 10 条互链，没有「系列 / 同年 / 主演」这类亲属关系 |
| 3 | **回访动机弱** | 671 条资源，用户无从知道「哪些看过」「最近上了什么」「哪部值得看」，站点侧零用户状态 |
| 4 | **链接失效全靠人工普查** | 见 [changelog-变更记录.md](changelog-变更记录.md)：取消分享 6 条、拒出链 5 条、清 56 条空目录…… 站点侧仍默认「所有链接永远有效」，失效是事后才发现 |

## 二、现状数据（决策依据）

**分类严重失衡**（2026-10-13 统计，`data/*.yaml`）：

| 分类 | 条数 | 分类 | 条数 |
|---|---|---|---|
| 电影 | 335 | 游戏 | 8 |
| 软件 | 112 | 电子书 | 8 |
| 电视剧 | 105 | 动漫 | 6 |
| 纪录片 | 86 | 操作系统 | 6 |
| — | — | 其他 | 5 |

两点推论：

- 后五个分类连首页 `homePerCategory: 5` 的一行都填不满，点进分类页只剩几张卡。这是**内容结构问题，不是 UI 问题**——硬凑内容只会拉低全站质量。
- 电影 335 条占全站一半，`pageSize: 35` 意味着要连点 10 次「加载更多」。**用户到不了第 200 条之后的内容，存量的一半是死库存。**

## 三、建议清单

成本标：**S** ≈ 半天 / **M** ≈ 1–2 天 / **L** ≈ 3 天以上（含内容投入）。

### A 组 · 用户侧发现与回访（纯前端，不改 URL，SEO 零风险）

| 编号 | 建议 | 打哪个瓶颈 | 落地要点 | 成本 |
|---|---|---|---|---|
| A1 | 详情页「链接失效一键反馈」 | 4 | `detailPage()` 加按钮，`mailto:` 预填标题 / id / URL，复用 `about` 页已有的邮箱 + QQ 双通道。零后端，不破「无登录」定位 | S |
| A2 | 收藏 / 看过（localStorage） | 3 | `theme/assets/card.js` 加角标按钮，`app.js` 维护 `wodewangpan:saved` / `:seen` 两个集合；列表页加「只看未看 / 只看收藏」开关 | M |
| A3 | 排序与筛选（JS 视图） | 3 + 翻页深 | 排序：入库时间 / 发行年份 / 标题拼音；筛选：网盘来源（夸克 / 百度 / 阿里）、有无提取码。需在 `search-index.json` 补 `date`、`kinds` 字段 | M |
| A4 | 详情页「上一个 / 下一个 + 随机」 | 2 | 同分类相邻两条，构建期静态输出（能被抓，比纯 JS 强） | S |
| A5 | `manifest.webmanifest` + 深色模式 | 留存 | manifest 一步就能「添加到主屏幕」；深色走 `prefers-color-scheme`，`style.css` 的 `:root` 已是令牌化设计 | S / M |

> ⚠️ **A2 / A3 的红线**：任何视图状态都**不得进 URL、canonical、sitemap**。`robots.txt` 已挡 `?q=`，新增参数要同步补一行，并在 Nginx 侧确认不会被外部链进来。
> ⚠️ **A3 的前置检查**：`app.js` 的注释已写明索引里没有 `added` 字段（`isNew` 是构建端算好的）。补字段前**先算 `search-index.json` 体积**——那是全站每个列表页都要拉的文件。
> 💡 A2 / A3 建议在 `config/site.yaml` 加一个开关（`views: [sort, saved]`）渐进放开，默认只开排序。

### B 组 · 内容结构化（对抗同质化的主力）

| 编号 | 建议 | 打哪个瓶颈 | 落地要点 | 成本 |
|---|---|---|---|---|
| B1 | `series` 字段 + 系列聚合 | 2 | YAML 加可选 `series:` / `series_no:`。现状是痛点：「速度与激情」拆成 11 条、「火线兄弟 Brothers Under Fire」把片名塞进 `tags` 当 hack。`relatedOf()` 只需加一层 series 加权，不必动现有关联逻辑 | M（回填是大头，可脚本半自动） |
| B2 | 年份 / 年代切面 | 2 + 翻页深 | 按 `date` 前四位构建聚合页。单年份几十条 vs 电影分类 335 条，Jaccard 天然低，**不会触发去重告警**。只对电影 / 电视剧 / 动漫生成，别给「其他」造出 5 条的年份页 | M |
| B3 | 规格字段（画质 / 集数 / 大小 / 字幕 / 版本） | 1 | 用户真搜的是「1080p 网盘」「4K 中字」「中文版」，现在全淹在简介里。加 `spec: [...]` 后用详情页现成的 `.facts` 表展示，**不必新增视觉**。新入库强制，存量慢慢补 | M（回填量） |
| B4 | 结构化评分字段 | 1 | 现在评分埋在简介末尾的 `｜TMDB 7.1` 里，机器读不到、搜索也吃不到。加 `rating:` 进 JSON-LD 的 `aggregateRating`，配合 B1/B2 自然长出「本站 8 分以上」这类切面 | S（代码）/ M（回填） |
| B5 | 分类页导语 + FAQ | 1 | 每分类 100–200 字导语 + 3 个 FAQ（怎么转存 / 有提取码吗 / 链接失效怎么办），挂 `FAQPage` JSON-LD。**必须分类定制，九个分类套同一模板等于没写** | M |
| B6 | 人工策展专题（片单 / 合集） | 1 | 新建 `data/editorial/`（或并入 `data/`，注意同步 [dev-开发注意事项.md](dev-开发注意事项.md) §三的 `NON_RESOURCE_FILES`），每条 = 编者按 + 条目 id 列表，生成 `/topic/<slug>/`。**限量：每月 1–2 篇，宁缺毋滥**，凑出来的片单本身就是薄内容 | S（代码）/ L（内容） |

### C 组 · 可靠性工程化（最省人工，建议优先）

| 编号 | 建议 | 打哪个瓶颈 | 落地要点 | 成本 |
|---|---|---|---|---|
| C1 | 失效自动降级 | 4 | YAML 加可选 `dead: true`，由 skill 的 `check-share-links.mjs` 写回 → 构建期：① 从列表 / 首页 / `/all/` 剔出；② 详情页保留但显示「链接已失效」+ `noindex` + 移出 sitemap。**比直接删条目温和**：保住已收录页的跳转价值，也不让蜘蛛吃硬 404 | M |
| C2 | `public/` 残留自动回收 | 4 | [changelog-变更记录.md](changelog-变更记录.md) 明确记着「构建不会自动回收已删条目的旧产物，必须手工清」。`build.js` 已有 `prune(dir, keep)`，把 `resource/*/`、`img/*`、`qr/*` 纳入同一 keep 集合即可。这条欠账清掉后，「下架一条资源」从四步变一步 | S |
| C3 | 每周定时体检 + CI 冒烟 | 4 | VPS cron 周跑 `check-share-links.mjs` → 汇总或直接写 C1 的 `dead`；GitHub Actions 做 YAML 规范 + 重复 id + 构建 + 首页 200 冒烟 | M |

### D 组 · SEO 引流补丁（补现有 todo 没覆盖的）

| 编号 | 建议 | 说明 |
|---|---|---|
| D1 | 补齐 `verification` | `config/site.yaml` 里五项全被注释掉 → **看不到任何一家后台的真实收录数据**，后面所有 SEO 判断都是猜。五家验证半小时搞定，**应排在所有 SEO 动作之前** |
| D2 | IndexNow（Bing / Yandex / Seznam） | [seo-收录与优化.md](seo-收录与优化.md) 已确认 Bing 全量推送通了，但那是「等抓取」；IndexNow 是秒级通道。`deploy/` 已有 `submit-baidu` 的范式，照着加一个 |
| D3 | 详情页专属 OG 图 | 现在 `og:image` 直接用竖版海报 240×360，`summary_large_image` 下被裁得难看。复用 `tools/share-poster.mjs` / `icon-poster.mjs` 合成 1200×630。**先只给新增和热门生成**，671 张全量会显著拖大产物与构建时间 |
| D4 | 首页瘦身 | 已在 todo：102KB，大头是 noscript 里 663 条详情页链接。方案建议收敛为「noscript 只出 9 个分类 + `/all/`」，详情页全量链接交给 `/all/` 承担——这本就是它 `allPage()` 的设计职责，不必在首页重复一份 |

> D1 / D2 是 [todo-待办清单.md](todo-待办清单.md) 二节里已有项的补充，不是替代：**补 verification 拿到数据 → 才谈得上按数据调优先级**。

## 四、明确不做（别删，防重提）

| 不做 | 为什么 |
|---|---|
| 评论 / 登录 / 积分 / 用户投稿 | 与「无数据库、无后端、无登录」的定位冲突，收益远小于合规与维护成本 |
| 在线播放 / 视频解析 | 香港节点带宽成本高，版权风险跳一个量级，且毁掉「静态秒开」的体验优势 |
| 自动采集同类站内容扩条目 | 直接加深瓶颈 1。本站价值是「精选 + 有质量的简介」，不是数量 |
| 给短板分类硬凑内容 | 动漫 6 / 操作系统 6 / 其他 5，是因为网盘里本来没有。更好的做法是 B6 专题 + 分类页「求资源」入口（mailto 预填），把短板变成互动位 |
| Service Worker 全站离线缓存 | 会破坏 [dev-开发注意事项.md](dev-开发注意事项.md) §四那套「内容未变不覆盖 / 命中 304」机制 |

## 五、推进顺序

**第一轮 · 低成本 + 直接降本（约两周）**
`D1 验证码` → `C2 产物清理` → `C1 失效降级` → `A1 失效反馈` → `C3 定时体检`
> 这一轮几乎全是「减少手工」和「让决策有数据」，做完后维护与 SEO 判断换一个量级。

**第二轮 · 内容资产化（约一个月）**
`B3 规格字段` → `B1 series` → `B5 分类导语` → `A4 上/下一个` → `A3 排序筛选`

**第三轮 · 增长**
`B2 年份切面` → `A2 收藏/看过` → `D3 详情 OG` → `D4 首页瘦身` → `B6 策展专题`（常态化，每月 1–2 篇）

**并行常跑**：`D2 IndexNow` 与现有 sitemap 推送一起。
