## 四、当前三个问题

### 1. 百度断更 9 天，配额推不完（优先级最高）

百度末次到访停在 **10-11**，而 `submit-baidu` 每天 03:10 只推 **10 条**，日志里「待推送还剩」长期在 657~683 之间循环——**推完一轮又因新增而回到起点，配额全耗在全量资源页上**。

### 2. 下架资源的历史 URL 还在被 Google 抓，每天 4~7 次 404

近 5 天 Googlebot 的 404 分两类：

- `/resource/{id}/` 共 39 次，涉及 15 个 ID（`an-002`、`app-034`、`app-106`、`app-116`、`mv-260`、`tv-015/077/079/084/085/089/093/102/108/150`），**10-12 起每天都有**；
- `/img/{id}-240.webp`、`-60.webp` 等 37 次，是同一批 ID 的海报。

已核验：这些 ID 在 `public/` 与 `sitemap.xml` 中**均不存在**，而当前构建自校验「HTML 里 10,690 处 `/img/*.webp` 引用，指向缺失文件 0 个」——所以**不是构建缺图 bug，是资源下架/改号后旧 URL 留在 Google 索引里**，它每天照旧来取，每次还回一整个 404 页。

### 3. Yandex 自 10-17 起没再来

它此前是覆盖最广的引擎（596 内容页）。单次断档不必紧张，但若连续一周不来，就要查 sitemap 是否被抓、IndexNow 是否还在正常递交。

## 五、待办

- [ ] **百度换策略**：把每天 10 条配额用在高价值页（分类页、`/tag/` 热门标签页、新上架资源），而不是全量硬推；同时在百度站长「普通收录」里做一次 sitemap 提交作为兜底。
- [ ] **给下架资源留信号**：构建时输出一份「已下架 ID 清单」，nginx 据此对 `/resource/{id}/` 与其 `/img/` 海报返回 **410 Gone**（或 301 到对应分类页）。与 `/resource/*/search-index.json` 的 410 同一套路，实测能把重试量从 80 次/天压到 2 次/天。
- [ ] **补齐中文引擎通道**：360 与搜狗站长平台提交 sitemap（字节 10-13 起自己来了，可先观察）。目前中文引擎里只有百度在 10-11 前抓过 2 个内容页。
- [ ] **UV 序列做进周报**：把本文第三节的按天 UV 用 `sitestats.py` 的 `daily_uv` 直接导出，别再用自报 PV 判断增长。
