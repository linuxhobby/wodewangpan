### 2026-10-22 · 分享从「页面链接」改为「资源包文本」，并删掉四个平台按钮

起因：QQ 群里分享本站链接，卡片降级成「站点名 + 裸 URL」，没有标题也没有描述。查下来页面侧没问题——`og:title` / `og:description` / `og:image` 完整正确，抓取器 UA 实测 200 可达；差异全在腾讯抓取器那一侧（日志里它对同一 URL 连抓两次拿到的是 301，而非规范形态的 URL 才会 301）。

结论不是去修卡片，而是**不再把展示效果押在平台抓取上**：分享 / 复制的 payload 从「一个 URL」改成一段多行资源包文本，网盘在前、页面在后。卡片渲染得好是加分，渲染得烂也不丢信息。

顺带删掉 `QQ / 微博 / 𝕏 / Telegram` 四个平台外链：`connect.qq.com/widget/shareqq` 是腾讯 2010 年代的组件，已经失效（死链）；其余三个对国内网盘站使用率近零，却占着详情页显眼位置。只留「分享」+「复制资源信息」。

完整口径见 [share-资源分享功能.md](share-资源分享功能.md)。

### 2026-10-28 · 反馈条从「只收失效」扩到「也收许愿」

提示语改成「资源许愿、链接打不开或资源有误？」，邮件主题从 `[失效反馈]` 改成 `[资源反馈]`，正文在「资源 / ID / 页面」之后由一行「问题」拆成两行：

```
反馈类型：（链接打不开 / 文件损坏 / 内容有误 / 想找的资源 / 其他）
说明：（请描述；选「想找的资源」请写清名称、年份或版本）
```

理由：只写「失效」时，找不到某个资源的用户看着入口也不像是对自己开放的，白白丢掉一批真实需求；而许愿邮件如果还顶着「失效反馈」的主题进来，站长一眼看上去会当成坏链去处理。类型那行是给快速分拣用的，说明那行才写内容——合成一行会两边都不清楚。

「暂无可用链接？」那条分支（无链接资源）保持原样：那种页面用户本来就是来找源的，不需要再区分类型。

### 2026-10-21 · 详情页反馈条：每个资源页都有「加入QQ群 / 邮件反馈」入口

规划里 A1「链接失效一键反馈」落地，顺带解决「资源页没有加群入口」——两件事本就是同一个位置，合成一个组件做。位置在转存链接**正下方**：用户刚发现链接打不开，此刻意图最强，放在别处都是猜。

三条取舍，改这块之前先看：

- **详情页不放二维码**。海报旁 `qrbox` 是资源转存码，同屏再放一个群码会被扫错，而扫错的后果比扫错链接更糟（存错文件能删，加错群是一次打扰）。`qm.qq.com` 落地页自己解决两端——手机拉起 QQ、PC 自带二维码——这里给纯链接就够。
- **不用 `--brand` 实底按钮**。加群是兜底动作，不该抢「打开 / 复制链接」的视觉焦点，所以只用虚线框 + `--fill-soft` 中性底，与上面的 `.linkrow` 拉开层次。
- **邮件预填定位信息**：`mailto:` 带 `[失效反馈] 标题` 主题，正文四行「资源 / ID / 页面 / 问题」，收到即可定位到是哪条，不用回信追问。

开关在 `config/site.yaml` 的 `detailFeedback`（默认开，写 `false` 全站详情页不渲染）；QQ 与邮箱任一缺失就只出另一个，都缺则整条不渲染。

**已验证（2026-10-21）**：微信内置浏览器能正常打开 `qm.qq.com/q/UkO8hrPaQ`，直接跳到申请加群页面，**不存在拦截**。所以反馈条维持纯链接形态，不必为微信单独出二维码或加 UA 分支——这条结论也解释了为什么详情页一开始就不该放群二维码。

一个附带观察：跳过去是「申请加群」而不是直接进群，说明群开了加群确认。用户点完还要等你通过，反馈的即时性会打折。想省掉这一步就把群设成「允许任何人加入」，代价是垃圾进群的风险上升——**建议维持现状**，失效反馈本来就不是分秒必争的事，多一道人工闸门反而过滤掉了误触。
