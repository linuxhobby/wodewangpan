# 资源分享功能说明

详情页分享入口做的是**把资源本身发出去**，不是把站点页面发出去。分享 / 复制的 payload 是一段多行的「资源包」文本，顺序为**网盘在前、页面在后**。方案是「移动端系统分享面板 + 桌面端一键复制」的渐进增强组合，纯前端、零后端依赖。

## 为什么不分享一个 URL

早期版本分享 / 复制的都是资源页 canonical，有三个问题：

1. **卡片长什么样由平台方决定**。腾讯抓不抓、跟不跟随 301、抓成什么样都不归我们管（2026-10-22 实测：QQ 群卡片降级成「站点名 + 裸 URL」，而页面 OG 标签本身是完整正确的）。把展示效果外包给第三方抓取器，等于把最在意的东西交给不可控因素。
2. **群里的人要多走一步**。拿到页面链接还得点进去、再点转存。
3. **分享者的目的不是请人来看站**，是让人拿到资源。把页面链接顶在最前面等于给朋友卡一道。

改成资源包文本后，信息写进**消息正文**——这是唯一 100% 可控的部分。卡片渲染得好是加分，渲染得烂也不丢信息。

## 分享内容格式

```
{标题}（{年份}） · {分类}
{一句话概要}
{网盘名}：{链接}
{网盘名}：{链接} 提取码 {code}
更多同类 → {资源页 canonical}
```

- 有 `date` 才带年份；多条网盘链接时每个一行；带提取码的追加在行尾。
- 无可用链接时，链接行写成「（暂无可用链接，页面会更新补源）」，页面链接照常给。

**一句话概要**取简介的第一句（`summaryOf()`，上限 60 字）。简介已补到 300 字，整段放进去会淹没链接，所以只取首句；两处脏数据必须处理：

1. 简介尾部常带「｜TMDB 7.1」这类标注，先按全角 `｜` 切掉，否则可能截出「…｜TMDB」。
2. 硬截会切出半截词（实测 「…全球月活」），所以优先退到上限内最后一个句读处再断，退得太狠（不足 6 成）才硬切——宁可长一点，也别砍成半句。
- **页面链接放在最后一行**，它的真实价值是兜底：网盘链接会失效，页面不会（失效了会标记 / 换源），所以它同时是长期入口和「更多同类」的引流位。

## 行为

### 桌面端

```
分享 · 复制资源信息 · 复制海报
```

- 「分享」：`navigator.share`；不支持的浏览器（如 Firefox 桌面）退化为复制——**复制的是资源包文本，不是 URL**。
- 「复制资源信息」：复制资源包（富文本，带海报，见「海报怎么进剪贴板」）。
- 「复制海报」：把海报当**图片文件**复制（见下），给微博这类不认 HTML 图片的地方用。
- 微信二维码单独一行（见下）。

### 触屏移动端

支持 Web Share 时**只隐藏微信二维码那一行**（扫码分享得靠另一台设备，手机上没意义），**「复制资源信息」保留**。理由：系统面板是「分享出去」，复制是「放进剪贴板」，是两个不同动作；而资源包文本最可靠的落地方式恰恰是复制粘贴——它不经过任何平台的卡片渲染，藏掉等于砍掉最稳的那条路。

判定用媒体查询 `(hover: hover) and (pointer: fine)`。注意 `.share__hint` 是 `display: flex`，`hidden` 属性压不住它，需要 `.share__hint[hidden]` 显式 `display: none`。

### 已删除的平台按钮

原来的 `QQ / 微博 / 𝕏 / Telegram` 四个外链于 2026-10-22 删除，原因：

- `connect.qq.com/widget/shareqq` 是腾讯 2010 年代的组件，**已经失效**（死链）。
- 微博 / X / Telegram 对国内网盘资源站使用率近零，却占了详情页显眼位置，还稀释了真正高频的复制按钮。
- 它们分享出去的都只是页面链接，同样逃不掉卡片降级的问题。

## 海报怎么进剪贴板

「复制资源信息」复制的是**富文本**，不是纯文本：`navigator.clipboard.write()` 一次写两个 flavor——

| flavor | 内容 |
|---|---|
| `text/html` | 海报 `<img>` 在最前，其后是资源包各行（首行「片名（年份）· 分类」加粗） |
| `text/plain` | 与改前完全一致的多行资源包文本 |

粘到微信 / QQ / 飞书 / 邮件正文这类**认富文本**的目标，海报跟着文字一起出来；只吃纯文本的目标（多数手机输入法、部分 App）拿到的仍是原来那几行，**不丢信息**——这是同时写两个 flavor 的目的。

三个必须守住的口子：

1. **海报用绝对地址**（构建期 `baseUrl + /img/<id>-240.webp`）。相对路径粘到站外解析不出图。
2. **占位图不复制**。`/img/placeholder*` 那张「暂无配图」粘出去只会让人以为分享坏了。
3. **不支持就整段退回纯文本**，不做半吊子降级：`window.ClipboardItem` 缺失（老 Firefox）、`clipboard.write` 被拒、构造抛错，任何一种都走回 `writeText` → `execCommand('copy')`，行为与改前一致，不会出现「点下去什么都没复制上」。

### 微博为什么没图，以及「复制海报」

2026-10-30 实测：**微信粘贴有图，微博粘贴只有文字**。同一个剪贴板内容，差异全在接收方——

- 微信编辑器收下 `text/html`，连里面的 `<img>` 一起渲染。
- 微博编辑器粘贴时**把 HTML 剥成纯文本**（只留文字、话题、表情），`<img>` 一律丢掉。它唯一吃的图片形态是**剪贴板里的图片文件**，也就是平时截图粘贴进微博那条路。

所以另开一个「复制海报」按钮，写的是 `image/png` flavor（`text/plain` 顺带一起塞，编辑器肯同时收就一次到位，只收图的也不更差）。微博发一条带图资源 = 点「复制资源信息」粘文字 + 点「复制海报」粘图，两步。

两个实现上的硬约束：

1. **PNG 转码**：剪贴板的图片口味只认 `image/png`，站点配图是 webp（`-240.webp`），必须 `createImageBitmap` → canvas → `toBlob('image/png')` 转一手，直接把 webp blob 标成 `image/png` 会被拒。
2. **`write()` 必须同步发起**：`fetch` 图片是异步的，等它 resolve 再调 `clipboard.write()` 在 Safari 上会被判为「无用户手势」而失败。所以异步部分要塞进 `ClipboardItem` 的 **Promise 值**里——`write()` 在点击回调里同步调用，Safari / Chrome 都放行。

**没有把它并进「复制资源信息」**：同时写 `image/png` + `text/html` 时，微信大概率走图片分支，变成「只出图、丢文字」——为了微博把微信弄坏不划算。宁可多一个按钮。

### 没走的两条路

- **base64 内嵌（data URI）**：看起来最稳，实际两头不讨好——810 条资源每张动辄几十 KB，base64 还要再涨三成，整个 HTML 串塞进剪贴板；而微信 / QQ / 飞书 sanitize 时**普遍会剥掉 data URI**，钱花了还不一定出图。远程 URL 由接收方自己去取，反而干净。
- **把 `image/png` 并进「复制资源信息」**：微信会走图片分支，变成只出图、丢文字（见上）。已改为单独按钮。

### 已知限制

- 海报取的是详情页那张 240×360（与列表卡片同一张），粘出去是缩略图尺寸，不是原图——当前没有更大的变体，为它单独出一版要给 810 条资源再生成一遍图，性价比不够。
- 出图依赖**接收方能访问本站**（远程 URL 由它去取）。站点打不开时，图自然也出不来，但文字照旧。
- 移动端 `navigator.share` 走系统面板，海报**不会**跟着走——Web Share Level 2 的 `files` 要 `canShare` 判定 + 把图 fetch 成 File，覆盖面和稳定性都不如现在的纯文本路径，暂不做。

## 微信分享的两种路径

微信网页分享没有官方 JS SDK（需公众号 + 后端签名），因此：

1. **扫码分享本页**：分享区放一张**本页 URL 的二维码**（`/qr/share-<id>.svg`），文案「微信：扫一扫，把本页分享给好友」。
2. **系统面板**：移动端「分享」按钮调起系统面板，里面直接有微信。

注意与「扫码转存」区分：详情页左侧 `qrBlock` 的二维码内容是**网盘转存深链**，分享区的二维码内容是**资源页 canonical URL**，二者不同，不要混用。

## 实现位置

| 文件 | 职责 |
|---|---|
| `scripts/lib/render.js` | `shareTextOf(item, shareUrl)` 拼资源包文本（构建期）；`sharePoster` 拼海报绝对地址（占位图判空）；详情页 `.detail__share` 模板：「分享」按钮（`data-share` / `data-url` / `data-title` / `data-text` / `data-poster`）+ `.share__panel`（复制按钮 `data-copy` + `data-poster`、本页二维码提示）。 |
| `theme/assets/app.js` | `copyPoster(btn, url, text)` 复制图片文件（`toPng()` 转码，Promise 值喂给 `ClipboardItem`）；`copyPacket(btn, text, poster)` 统一入口：有 `data-poster` 且支持 `ClipboardItem` 就写 `text/html` + `text/plain`，否则 `plainCopy()`（原逻辑）；`packetHtml()` 生成带海报的富文本；`flash()` 给「已复制」反馈。点击 `[data-share]`：支持 `navigator.share` 则调系统面板（传 `title` + 资源包 `text` + `url`），否则调 `copyPacket`。init 里用媒体查询判定触屏移动端并隐藏面板。 |
| `theme/assets/style.css` | `.detail__share`（flex 同行）、`.share__panel`（`display: contents`，让内部子元素与「分享」按钮排同一行）、`.share__hint`（`flex-basis: 100%` 强制微信二维码换行）、`.share__qr` 样式。 |
| `scripts/lib/assets.js` | `writeShareQr(pageUrl, id, outDir)`：为每个资源生成本页 URL 的二维码 SVG，写入 `public/qr/share-<id>.svg`（依赖 `qrcode` 包）。 |
| `scripts/build.js` | 构建期调用 `writeShareQr` 生成 `shareQrMap`，把 `shareQr` 路径注入 `detailPage` 的 `ctx`。 |

## 隐私口径

分享功能纯前端、不发任何统计请求，与 `/about/`「不追踪个人信息」的口径一致，无需改文案。

## 部署

构建时 `npm run build` 会为每个资源自动生成 `public/qr/share-<id>.svg`，VPS 拉取重建即生效，无需手动操作（首次部署记得 `git pull`）。

## 已知限制

- 资源包文本里的网盘链接是构建期从 YAML 取值，**入库后如果网盘换链，要重新构建才会更新**；分享出去的旧文本不会变。
- 分享依赖资源页 canonical（`baseUrl + /resource/<id>/`），`baseUrl` 需在 `config/site.yaml` 或 `BASE_URL` 环境变量正确配置，否则生成的链接会指向错误域名。
- 微信真正「一键分享给好友」只能靠移动端系统面板或扫码，网页端无法做到免扫码直达。
- QQ 群卡片是否显示完整标题 / 描述，取决于腾讯抓取器的行为（新链接异步抓取、是否跟随重定向、域名是否备案），**站点侧无法干预**。这也是本功能改为「信息写进正文」的直接原因——不把效果押在它身上。
