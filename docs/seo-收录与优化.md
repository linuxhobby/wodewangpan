## 二、抓取预算：实测与结论

**偏科数据**：首页被抓 583 次（约七成配额），资源页仅覆盖 159/702。

### 已验证的结论

- **304 才是腾预算的手段**。原先每小时全量重建 → 700 多个详情页 mtime / ETag 每次刷新 → `If-Modified-Since` 永远不命中（日志特征：200×810，几乎无 304）。改成「内容未变不覆盖」后，重复访问从 200 变 304，预算自然腾给新页。
- **静态资源版本号必须跟内容走，不能跟 commit 走**。用 commit 的话每个提交都改一遍所有页面的 CSS/JS 链接，700 多页内容全变、mtime 全量刷新，304 照样落空。

### 被推翻的结论（别再走回头路）

- ~~冻结首页 `<lastmod>` 以省预算~~ → **不要做**。首页按分类各取最新几条（`homePerCategory`），任何分类新增都会改变首页，lastmod 是真实信号，人为冻结会让 Google 判定其不可信。
- ~~调 `<priority>` / `<changefreq>`~~ → **没用**，Google 官方忽略这两个字段。
- ~~整条屏蔽 `search-index.json`~~ → **只挡子路径**。线上实测根路径是 200，404 全在 `/resource/<id>/search-index.json` 这类子路径上（`app.js` 早期用相对路径取索引留下的历史残留，10-09 已改根绝对路径，蜘蛛仍按记忆重试、逐日递增）。根路径是 Googlebot 渲染「加载更多」的通道，一起挡等于自断一条发现路径。

### 待观察

- Bing Webmaster Tools 的 sitemap 于 10-10 提交，等 1~2 周看 Crawl stats 是否起量。
- 360 那边核对 301 链是否**单跳**直达 `https://www.<域名>/`。

## 四、优化项（按性价比排序）

- [x] **只清理 `search-index.json` 的子路径残留**：`robots.txt` 加 `Disallow: /*/search-index.json`（只匹配带目录前缀的），Nginx 对 `^/.+/search-index\.json$` 返回 **410**（比 404 衰退更快，且不依赖引擎是否支持通配）。10-09 的 80 次/天 → 10-11 的 2 次/天。
- [x] **内部接口屏蔽**：`Disallow: /stats.json`、`Disallow: /hit` 已加入并复查确认。
- [x] **构建改「内容未变不覆盖」**：实测二次构建 722 个文件全部沿用、0 个重写（58.7s → 34.9s）。首页 `<lastmod>` 因此不需要人为冻结。
- [x] **重建频率定为每 2 小时**：脚本先比对 HEAD，没新提交就 `exit 0`，所以频率只决定「提交后多久上线」（≤2h），空跑成本只有一次 `git fetch`，可以调密。急发走 `FORCE=1 site-autoupdate`。
- [ ] **百度破局**：天花板是资质不是技术。能做的仍是平台提交 sitemap +「普通收录 → API 推送」（已有 `submit-baidu`），并把推送顺序改成**详情页优先**（首页它自己天天来，不占配额）。真正破局要等备案 + 大陆节点，列为长期项。
- [ ] **新引擎破零**：搜狗 / 字节 / 华为零到访，只能在各自站长平台提交 sitemap 引蜘蛛（均无开放 API，一次性动作）。
- [ ] **首页体积与去重**：见第三节。
