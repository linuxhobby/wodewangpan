## 三、判定标准（精确口径，务必照此计算）

字数由 `scripts/lib/data.js` 的 `bodyLength()` 计算，是全站唯一口径：

```js
export function bodyLength(text) {
  return [...String(text || '')
    .replace(/【[^】]*】/g, '')        // 剥掉【第 1 季 · 共 12 集】这类标签
    .replace(/｜[^｜]{1,40}\s*$/, '')  // 剥掉结尾｜TMDB 8.5 / ｜作者：xxx 署名
    .trim()].length;                  // 按 Unicode 字符计，中文一字一符
}
```

**要点**：

- `【…】` 标签和 `｜…` 署名**不计入字数**，所以正文要写满 300 字本身。
- 结尾的 `｜TMDB 8.5` 之类是数据来源署名，**不能删**，工具会自动接回。
- 建议写到 **320–400 字**，留点余量，别贴着 300 卡线。

## 四、执行流程（工具链已就绪，直接用）

```bash
# 1. 拿到待补清单（同时写入 .tmp/short-desc.md，按字数升序，最该先补的排最前）
npm run list:short
npm run list:short -- --cat=纪录片        # 只看某个分类
npm run list:short -- --limit=50          # 只列前 50 条

# 2. 把改写好的正文写进草稿文件（JSON，键是资源 id）
#    .tmp/desc-draft.json  →  { "dc-077": "新正文……", "tv-001": "新正文……" }

# 3. 空跑：只打印将要改成什么，不写盘
node tools/fill-desc.mjs

# 4. 确认无误后落盘
node tools/fill-desc.mjs --apply

# 5. 验收
npm run list:short      # 应输出「没有正文少于 300 字的条目」
npm run build           # SEO 提醒里不该再有薄内容那条
```

`tools/fill-desc.mjs` 的行为（已确认）：

- 按 `- id: xxx` 定位条目块，**只改 `description` 那一行**，其余字段一字不动。
- 自动把原有的 `【第 N 季 · 共 M 集】` 头 和 `｜TMDB x.x` 后缀接回新正文。
- 以 JSON 双引号标量写回，中文 / 引号 / 换行不会破坏 YAML。
- 加 `--strict` 可让不足 300 字的草稿直接跳过不写入。

**建议分批**：每批 30–50 条，跑一次 `--apply` 后 `npm run build` 验一遍，别一次灌 387 条。

## 五、内容要求（这部分决定任务成败）

### 必须做到

1. **原创改写，不许照抄**。TMDB / 豆瓣的简介原文不能直接搬——网上到处都是，抄来等于又造一批重复内容，对 SEO 毫无价值。要换角度、换结构、用自己的话重写。
2. **写具体，不写套话**。说清楚：
   - 这是什么（类型、年代 / 版本、背景）
   - 核心看点是什么（讲了个什么故事 / 解决什么问题 / 有什么独到的地方）
   - 适合谁（给什么人看、什么场景下用）
3. **每条要有区分度**。387 条不能套同一个模板，开头句式、叙述顺序要有变化。

### 禁止

- 关键词堆砌（为凑字数反复塞"网盘资源""下载""高清"之类）
- **编造事实**：不确定的演员表、章节、获奖记录、评分、版本号，一律不写。宁可写得朴素，不能胡编。
- 空洞形容词堆砌（"精彩纷呈""值得一看""震撼人心"）
- 把同一段话换个片名复用

### 特殊情况

- **软件类**：写清它是干什么的、解决什么痛点、相比同类有什么不同、适合什么平台/人群。别写成说明书，也别只抄官网文案。
- **纪录片**：写清题材、视角、讲了什么，以及适合什么兴趣的观众。
- **电视剧**：写清题材、主线、风格；开头若有 `【第 N 季 · 共 M 集】`，**不要自己加**，工具会从原文接回。
- 原文末尾的 `｜TMDB 8.5` / `｜作者：[美] xxx` 是数据署名，**草稿里不要写**，工具自动补。

- 改完必须 `npm run build` 跑通、无报错。

## 八、已知陷阱

1. **字数口径**：曾经 `tools/fill-desc.mjs` 自带一份 `bodyLen`，只剥开头的 `【…】` 且限 30 字，和构建用的 `bodyLength`（全剥）不一致，会出现"脚本说够了、构建还在告警"。**现已统一**，两者都用 `data.js` 的 `bodyLength` / `MIN_DESC`，不用再管。
2. **别给草稿加 `【…】` 头和 `｜…` 后缀**，工具会从原文接回；自己加会被判重复拼接。
3. **改完记得构建**——`data/*.yaml` 改了不构建，`public/` 里还是旧内容。
4. 构建时会跑 `syncHeaderCounts` 自动刷新各 YAML 头部的条数注释，看到注释行变化是正常的，不是改错。
